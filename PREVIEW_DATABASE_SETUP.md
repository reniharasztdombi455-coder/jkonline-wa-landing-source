# Preview-only database setup

This repository's `wrangler.toml` points to the Production D1 database. Do not use it to apply migrations or run destructive SQL during development.

## Safe Preview setup

1. Create a separate D1 database in Cloudflare named `whatsapp-landing-manager-preview-db`.
2. Copy its database ID into `wrangler.preview.toml`, replacing the placeholder. Do not use the Production database ID.
3. In the Cloudflare Pages Preview environment, bind the variable `DB` to that same Preview D1 database.
4. Initialize the Preview database with the manager repository's baseline `schema.sql`.
5. From this repository, apply the D1 migrations using the Preview-only config:

   ```sh
   npx wrangler d1 migrations apply whatsapp-landing-manager-preview-db --remote --config wrangler.preview.toml
   ```

6. Verify the migration status and test the Preview URL before considering any Production change.

## What the migrations create/change

- Per-link customer code counters and idempotent customer sessions.
- WhatsApp number pool, assignments, routing cycle, prefetch queue, and refill locks.
- Unique customer event records.
- Composite uniqueness for `(slug, customer_code)`. Codes are generated by a counter per landing link, so a global unique constraint on `customer_code` incorrectly causes unrelated links with the same prefix to collide.

## Production protection

Do not run `wrangler d1 migrations apply` with the Production `wrangler.toml` during this repair. No Production database has been changed by this branch.
